## 这次要验证什么

一次性生成 12 周计划的**稳定度**与**科学度**。动态调整（执行中途取消 / 超额完成如何影响后续排课）不在本轮范围。

## 怎么验

页面默认只显示**前两周**，点「查看完整 12 周」看全程。重点看这几处：

1. **周量曲线**是否合理递进——12 周应该在涨，减量周应该真的更轻
2. **强度分布**——高强度是否过密，硬课之间是否留够恢复
3. **课程内容**——每节课点开看段落结构，判断这节课本身编得对不对
4. **给用户的提示文案**——页面底部那几行小字，读起来是否讲人话、是否准确
5. **计划底部的自检结果**——15 条断言的实时结果

建议各自换不同输入多试几组，尤其是这几类边界：

- 表单全空（零基础）
- 只勾 1–2 个训练日
- 自报周量很高但训练日很少（比如 720 分钟 / 2 天）
- 填了「单次最多能骑 20 分钟」
- 场地选室内 / 室外，有无功率计各试一遍
- 六个目标各生成一份对比

## 已知边界（不是 bug，别重复报）

- 约 12% 的输入组合 12 周增长不足 5%——都是用户自己的约束顶死了（训练日太少配高自报量、室内课程最长 150 分钟、天数 × 单次上限已到物理上限）。页面会如实告知原因。
- 同一周偶尔出现两节相同的课——集中在「有氧耐力 30 分钟」和「轻松骑 20 分钟」两档，无功率计筛选后课程库里各只剩 1 节可选。是库的边界，补库即可消除。
- 选室内 + 高周量时会出现 150 分钟的室内长课。骑行台上骑这么久是真实的执行难度，要不要压是产品取舍。

## 验证状态

26,701 例仿真（3,960 组真实画像全组合 + 20,000 随机 fuzz + 2,741 恶性边缘输入）：

- 崩溃 0
- 引擎自带 15 条自检失败 0
- 用户硬约束违反 0（不排在未勾选的星期、不一天两节、不超单节上限、器材场地全匹配）
- 连续两天高强度 0
